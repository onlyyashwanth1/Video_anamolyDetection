Architecture

How a video becomes a score.

A video is sampled, encoded, grouped into 4-second windows and described in words. Each window is compared with a memory of normal footage, by picture and by caption, and a judge reads the caption next to the closest normal moments. The scores are added and mapped back onto every frame. No model is trained and no incident is described in advance.

At a glance

A video goes in. A score for every frame, alerts and a one-sentence description of every few seconds come out. Nothing is trained, and no list of incidents is written down anywhere.

The path of one video

Frames at 1 fps→Frame vectors→4-second windows→Captions→Centred caption vectors→Novelty and judge scores→Window score→Frame scores→Alerts
Three frozen models
  • CLIP ViT-L/14 turns frames into vectors that can be compared.
  • Gemma 4 31B writes what happens in each window and later acts as the judge.
  • MPNet turns captions into sentence vectors.
One fixed reference
  • Normal memory: every window of normal footage, as an image vector, a caption and a centred caption vector.
  • With it, how novel normal windows usually look, and how the judge usually rates them.
  • Prepared beforehand and never changed while a video is scored.

The whole score in four lines

B = z( 1 − max cos(caption, memory captions) ) + 0.25 · z( 1 − max cos(image, memory images) )
J = ( Gemma's expected rating − normal mean ) / normal std
window score = B + 1.0 · J
alert at frame f  if  smoothed mean of covering window scores > 3
0

Normal memory

Keep everything seen in normal footage, and learn how novel normal itself looks.

Takes
Videos in which nothing goes wrong
Gives
Window vectors, captions and their reference statistics

How it works

  1. Each normal video goes through steps 1 to 5 with the same frozen models.
  2. For every window, the memory keeps the image vector, the caption and the caption vector. Caption vectors are centred on their own video's mean.
  3. Every memory window is scored against the rest of the memory with its own video left out. The median and IQR / 1.349 of those novelties become the unit for test scores.
  4. A seeded sample of memory windows is rated by the judge. Their mean and standard deviation calibrate the judge.

Why it is there

"Abnormal" only has meaning against a normal. Calibrating the memory against itself puts every score in the same unit: spreads above what normal footage typically scores.

1–4

Perception

Turn the video into a list of 4-second windows, each with a vector and a sentence.

Takes
The video at its native frame rate
Gives
Per window: image vector and caption

How it works

  1. Sampling: keep one frame per second.
  2. Image vectors: CLIP ViT-L/14 encodes the whole frame at full and half size; the two vectors are averaged and normalised.
  3. Windows: 4 seconds long, starting every second; the window vector is the mean of its frame vectors.
  4. Captions: Gemma describes up to 4 frames of the window, then joins them into one sentence in time order.

Why it is there

Windows hold actions, not just poses. Captions put the action into words that can be searched by meaning and read by the judge. Whole frames are kept because the background is what the memory knows best.

5

Sentence vectors and centring

Remove what is always true of this camera, keep what is happening.

t̃ = normalise( MPNet(caption) − 1.0 · mean of MPNet over the video's captions )

Why it is there

Captions from one camera keep naming the same place. Without centring, a test video filmed somewhere the memory has never seen would look novel in every window. After centring, only change within the video stands out.

6–7

Novelty and the memory score B

How far is this window from the closest thing in normal memory?

zcap = ( 1 − max cos(t̃, centred memory captions) − median ) / (IQR / 1.349)
zimg = ( 1 − max cos(vwin, memory images) − median ) / (IQR / 1.349)
B = zcap + 0.25 · zimg

Why it is there

B uses no prompts at all. It flags whatever the memory has not seen, which is the core idea: watch normal, then notice the difference. Only the single nearest neighbour counts, so one close normal match is enough to call a window familiar.

8

Memory-aware judge

Novel is not the same as harmful. The judge weighs the difference.

  1. Retrieve the 8 most similar distinct captions from memory.
  2. Ask Gemma, with a fixed generic prompt, how likely the new moment is abnormal compared with those normal moments, as one digit from 0 to 9.
  3. Read the probabilities of the ten digit tokens and take the expected digit as the rating.
  4. Convert to z with the mean and standard deviation of normal memory ratings.

The prompt names no category of incident. Each rating is stored by its exact prompt and reused.

9

Fusion

Both terms are already in spreads above normal, so they are added.

window score = B + 1.0 · zJ
10–11

Frame scores and alerts

Map window scores back onto every original frame, smooth them, and alert above 3.

s(f) = mean of score(w) over windows covering f
ŝ(f) = centred moving average of s over min(36 s, length / 4)
alert(f) = ŝ(f) > 3   (shown as σ(ŝ − 3) > 0.5)

Smoothing joins the windows of one event into a single run of alerts. The level 3 is a rule, not a tuned value; ROC-AUC does not depend on it.
