Architecture

How a video becomes a score.

The default pipeline from our draw.io chart. A video is sampled, masked and encoded, grouped into 4-second windows and described in words. Each window is scored against written prompts and a memory of normal footage, and the result is mapped back onto every frame. No model is trained.

At a glance

A video goes in. A score for every frame, a list of alerts and a one-sentence description of every few seconds come out. Nothing in between is trained.

The path of one video

Frames at 1 fps→Masked frames→Frame vectors→4-second windows→Captions→Action and memory scores→Window score→Frame scores→Alerts
Three frozen models
  • YOLO-World v2 finds people and objects so the background can be blurred.
  • CLIP ViT-L/14 turns images and sentences into vectors that can be compared.
  • Gemma 4 31B writes down what happens in each window.
Two fixed references
  • Action prompt bank: 26 phrases describing normal activity and 26 describing incidents.
  • Normal memory bank: window vectors from normal footage, plus how far normal windows usually sit from each other.
  • Both are prepared beforehand and never change while a video is scored.

The whole score in four lines

action = 0.875 · σ(mimg / 0.1) + 0.125 · σ(mtxt / 0.1)
memory = σ( (d − median) / IQR )
window score = 0.95 · action + 0.05 · memory
alert at frame f  if  mean of covering window scores > 0.5935
1

Frame sampling

Reduce the video to one frame per second.

Takes
The video, at its native frame rate
Gives
One frame per second, each with its timestamp

How it works

OpenCV decodes the video and keeps every n-th frame, where n = round(native fps ÷ 1). A 30 fps video keeps frames 0, 30, 60 and so on.

Why it is there

Neighbouring frames are almost identical. Keeping one per second cuts the work for the large models about thirtyfold, and events that last a few seconds are still seen. Step 8 maps the scores back onto every original frame.

1 frame per secondNo model
2

Object-centric masking

Keep people and objects sharp and blur everything else.

Takes
A sampled frame
Gives
The same frame with its background blurred

How it works

  1. Detect. YOLO-World v2, an open-vocabulary detector, draws boxes around people and objects.
  2. Track. ByteTrack links the boxes from frame to frame, so each object keeps one ID through the video.
  3. Blur. Pixels outside every box are replaced with a 51 × 51 Gaussian-blurred copy. If nothing is detected, the frame is left unchanged.

Why it is there

Light, shadows, weather and moving trees change the picture without anything happening. Blurring them keeps the image encoder focused on the actors. Only the image vectors use masked frames; captioning in step 5 sees the original frames.

YOLO-World v2ByteTrack51 × 51 blur
3

CLIP image encoder

Turn each masked frame into a vector of 768 numbers.

Takes
A masked frame
Gives
A frame vector vt of length 1

How it works

CLIP ViT-L/14 encodes the frame twice: as it is, and after shrinking it to 112 × 112, half of CLIP's 224-pixel input. The two vectors are averaged and rescaled to length 1.

vt = normalise( ( f(x) + f(x½) ) / 2 )

Why it is there

CLIP places images and sentences in the same space. A frame can therefore be compared with a written description (step 6a) and with frames of normal footage (step 6b). The small copy adds a coarse view of the scene's layout.

CLIP ViT-L/14768 dimensionsfull + 0.5× scale
4

Sliding windows

Group the frame vectors into overlapping 4-second windows.

Takes
The sequence of frame vectors
Gives
One window vector vimg per window

How it works

A new window starts every second and covers the next 4 seconds, until a window reaches the end of the video. Its vector is the mean of the frame vectors inside it, rescaled to length 1. Most seconds belong to four windows.

vimg = normalise( mean of vt over the frames in the window )

Why it is there

Incidents unfold over seconds, so a window sees motion and context that a single frame cannot. Because windows overlap, no event can fall between two of them.

4 s window1 s strideNo model
5

Temporal captioning

Describe each window in one sentence.

Takes
The original, unmasked frames of a window
Gives
A summary sentence and its CLIP text vector vtxt

How it works

  1. Up to 4 evenly spaced frames are picked from the window.
  2. Gemma captions each frame. Captions are cached per frame, so overlapping windows reuse them.
  3. Gemma joins the timestamped captions, in order, into one short sentence. It is told to describe only visible actions and not to judge whether anything is unusual.
  4. CLIP's text encoder turns the sentence into vtxt.

Why it is there

A sentence names actions directly, such as "two cars collide", which gives the scorer a second, word-based view of the window. It also gives every window a readable explanation.

After this step every window carries two vectors: vimg from its frames and vtxt from its caption.

Gemma 4 31B · Q8_0served by Ollamatemperature 0≤ 4 frames per window
6a

Action score

Does the window look more like an incident or more like ordinary activity?

Takes
vimg, vtxt and the action prompt bank
Gives
An action score between 0 and 1

How it works

The prompt bank holds 26 normal phrases, such as "people walking normally", and 26 anomalous ones, such as "vehicles colliding in a road accident". Each is encoded once with CLIP's text encoder.

For vimg and vtxt separately, the scorer finds the best-matching anomalous phrase and the best-matching normal phrase and subtracts their similarities. A sigmoid turns that margin into a probability. The image and caption probabilities are then mixed 7 to 1.

m = max sim(v, anomalous) − max sim(v, normal)
s = σ(m / 0.1)
action = 0.875 · simg + 0.125 · stxt

Why it is there

It turns a vague question into a comparison CLIP is good at. Using only the best match on each side means one strong description is not diluted by many unrelated ones. The image carries most of the weight; the caption adds a check in words.

26 + 26 promptsτ = 0.10.875 image · 0.125 caption
6b

Memory score

Has anything like this window been seen in normal footage?

Takes
vimg and the normal memory bank
Gives
A memory score between 0 and 1

How it works

The scorer finds the 10 memory windows most similar to vimg and turns their similarities into a distance d. It then compares d with the distances normal windows usually have. A typical normal window scores about 0.5 and a clearly unfamiliar one approaches 1.

d = 1 − ( 0.6 · mean of the top-10 similarities + 0.4 · best similarity )
memory = σ( (d − median) / IQR )

How the memory is prepared

  1. Normal footage, with no incidents, goes through steps 1 to 5 once.
  2. The videos are split 80 / 20 by video. Windows from the larger part are stored as the memory.
  3. Windows from the smaller part are compared with that memory. The median of their distances and its interquartile range (IQR) are stored with it.

The memory never changes while videos are scored. It also stores caption vectors, but the caption memory has zero weight in this model.

Why it is there

Prompts only cover what someone wrote down. The memory notices moments that look unlike normal footage even when no prompt describes them. Calibrating with the median and IQR puts the distance on a common scale.

k = 10 neighbours0.6 mean + 0.4 maxmedian / IQR calibration
7

Fusion

Blend the two scores into one score per window.

Takes
The action score and the memory score
Gives
One window score between 0 and 1

How it works

A weighted average. The action score carries most of the decision. The memory score pushes unfamiliar windows slightly up and familiar ones slightly down.

window score = 0.95 · action + 0.05 · memory

Why it is there

The two scores answer different questions. Fusing them gives one number per window that both kinds of evidence can move.

95% action5% memory
8

Frame projection

Give every original frame a score.

Takes
The window scores
Gives
A score for every frame of the original video

How it works

Each frame takes the mean score of all windows that cover it. With 4-second windows and a 1-second stride, most frames are covered by four windows; frames near the start and end are covered by fewer.

s(f) = (1 / |Wf|) · Σ window score, over the windows Wf that contain frame f

Why it is there

The result lines up with the original video frame by frame. Averaging overlapping windows also smooths the curve, so one odd window cannot cause a spike on its own.

Mean of overlapping windowsNo model
9

Alert

Turn each frame's score into a yes or no.

Takes
The frame scores
Gives
An alert flag for every frame

How it works

A frame raises an alert when its score is above the threshold. The threshold only decides which frames are flagged; the scores themselves stay the same.

alert(f) = s(f) > 0.5935

Why it is there

A fixed threshold gives a simple, repeatable rule. Raising it gives fewer, more confident alerts. Lowering it catches more incidents at the cost of more false alarms.

Threshold 0.5935
·

Outputs

What the pipeline returns for each video.

  1. Frame scores. An anomaly score for every frame of the original video.
  2. Alerts. The frames, and so the time ranges, whose score is above the threshold.
  3. Window records. For every window: its time span, caption, action, memory and window scores, and the caption of its closest normal memory window.
